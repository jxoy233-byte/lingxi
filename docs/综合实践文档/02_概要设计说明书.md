## 第1章 引言

### 1.1 编写目的

本文档是"智析（Zhixi）多智能体数据分析对话系统"的**概要设计说明书**（High-Level Design，HLD）。本文档以"需求规格说明书"为输入，对系统的总体架构、模块划分、关键流程、接口契约、数据存储等进行宏观设计。

本文档的目标：

1. **架构定调**：明确系统采用的分层架构、技术栈与部署形态；
2. **模块切分**：将系统拆分为职责单一、可独立演进的模块；
3. **接口契约**：定义模块间接口、API 接口、数据契约；
4. **流程贯通**：通过 UML 时序图、协作图、状态图、活动图等贯通关键业务场景；
5. **为详细设计提供骨架**：作为后续详细设计说明书的设计基线。

### 1.2 设计原则

| 原则         | 描述                                          |
| ---------- | ------------------------------------------- |
| **单一职责**   | 每个模块只负责一个明确的领域能力，类/函数保持"小而美"                |
| **分层解耦**   | 严格分层（接口层 / 业务层 / 核心层 / 工具层 / 基础设施层），禁止跨层调用  |
| **依赖倒置**   | 高层模块不直接依赖低层模块的具体实现，而是依赖抽象接口（如 ILLMProvider） |
| **开闭原则**   | 对扩展开放，对修改关闭。新增 LLM Provider、新增工具只需新增实现类     |
| **状态外部化**  | 所有会话状态、检查点、记忆均外部化（Redis / 文件），便于持久化与回溯      |
| **安全纵深防御** | 容器沙盒 + 危险命令拦截 + 路径校验 + 日志脱敏多重防护             |
| **可观测性**   | 所有关键节点均有日志埋点，支持日志回溯与状态检查                    |

### 1.3 设计约束

- 后端采用 Python 3.12+ 与 FastAPI 异步框架；
- 状态图采用业界主流的多智能体编排框架；
- 前端采用 Vue 3 + Vite；桌面端基于 Electron；
- 数据持久化使用 Redis（内存 KV + 可选 RDB 持久化）；
- 沙盒执行使用 Docker 容器，预启动池化；
- 多模态解析支持 ≥ 6 种格式；
- 兼容多家 LLM 服务商（OpenAI 兼容 API）。

## 第2章 系统总体设计

### 2.1 系统架构风格

本系统采用**分层架构 + 事件驱动 + 状态图**的混合架构风格：

| 架构元素 | 说明                              |
| ---- | ------------------------------- |
| 分层架构 | 自顶向下分为接口层、业务层、核心层、工具层、基础设施层     |
| 事件驱动 | 前端通过 SSE 监听后端流式事件；后端内部通过状态图事件传递 |
| 状态图  | 多智能体编排采用显式状态图，节点之间通过边和条件流转      |
| 容器化  | 沙盒执行环境采用 Docker 容器，进程级隔离        |
| 持久化  | Redis 同时承担缓存与检查点存储              |

## 第12章 出错处理

### 12.1 错误分类

| 类别             | 说明                           | 处理策略             |
| -------------- | ---------------------------- | ---------------- |
| **客户端错误（4xx）** | 请求格式错误、参数缺失、文件超大             | 返回详细错误信息         |
| **服务端错误（5xx）** | LLM 调用失败、Redis 不可用、Docker 异常 | 重试 + 降级 + 告警     |
| **业务错误**       | 危险命令、超时、内存不足                 | 友好提示 + 日志记录      |
| **系统错误**       | 框架异常、未捕获异常                   | 全局异常处理器 + 500 响应 |

### 12.2 关键错误处理策略

#### 12.2.1 LLM 调用失败

- **重试**：最多 3 次，指数退避；
- **降级**：使用备用模型；
- **失败**：返回用户友好提示，记录日志。

#### 12.2.2 Docker 异常

- **容器停止**：自动重建；
- **沙盒镜像缺失**：启动时检测，提示构建；
- **Docker 守护进程不可用**：返回错误，提示检查 Docker。

#### 12.2.3 Redis 异常

- **连接断开**：自动重连；
- **写失败**：本地缓存兜底；
- **读失败**：返回空，前端降级显示。

#### 12.2.4 文件解析失败

- **格式不支持**：返回错误，提示支持的格式；
- **解析超时**：返回部分结果，提示重试；
- **文件损坏**：返回错误，记录日志。

### 12.3 全局异常处理

```python
@app.exception_handler(Exception)
async def global_exception_handler(request, exc):
    logger.exception(f"Unhandled exception: {exc}")
    return JSONResponse(
        status_code=500,
        content={"error": "internal_error", "message": str(exc)},
    )
```

### 12.4 错误日志规范

| 级别       | 使用场景                |
| -------- | ------------------- |
| DEBUG    | 调试信息（默认关闭）          |
| INFO     | 关键节点状态变化            |
| WARNING  | 可恢复的异常（如危险命令拦截）     |
| ERROR    | 错误事件（如 LLM 调用失败）    |
| CRITICAL | 致命错误（如 Redis 完全不可用） |
