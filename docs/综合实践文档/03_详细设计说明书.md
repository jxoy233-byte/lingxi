## 第1章 引言

### 1.1 编写目的

本文档是"智析（Zhixi）多智能体数据分析对话系统"的**详细设计说明书**（Low-Level Design，LLD）。本文档以"概要设计说明书"为输入，对系统的核心模块、关键算法、数据结构进行详细描述，使开发人员能够直接据此编码。

本文档的核心目标：

1. **算法可视化**：使用程序流程图、N-S 盒图、Pad 图、判定表、判定树等多种结构化方法描述核心算法；
2. **接口精确化**：给出函数级接口签名、参数约束、返回值；
3. **数据结构具体化**：定义关键数据结构的字段、类型、约束；
4. **可测试性**：为每个模块提供测试要点，便于编写测试用例。

### 1.2 描述工具约定

本系统采用如下结构化描述工具：

| 工具         | 用途        | 说明                                         |
| ---------- | --------- | ------------------------------------------ |
| **程序流程图**  | 描述算法的整体流程 | 使用标准流程图符号（矩形 = 处理、菱形 = 判断、平行四边形 = 输入 / 输出） |
| **N-S 盒图** | 描述结构化算法   | 嵌套矩形，全部在矩形内                                |
| **Pad 图**  | 描述问题的逐步求解 | P（问题）→ A（抽象）→ D（细化）→ S（验证）                 |
| **判定表**    | 描述多条件组合   | 条件桩、动作桩、条件项、动作项                            |
| **判定树**    | 描述分层判定    | 树形结构，从根到叶                                  |
| **伪代码**    | 描述算法逻辑    | 类 Python 风格，可读性优先                          |

### 1.3 设计约束

- 严格遵守结构化程序设计原则：每个算法只有一个入口、一个出口；
- 程序流程图不允许使用箭头反向；
- 禁止使用 go to 类跳转；
- 每个判定节点最多 2 个分支（数值判断）或 3+ 个分支（枚举判断）。

## 第3章 多智能体工作流节点详细设计

### 3.1 主工作流概览

主工作流包含 6 个核心节点，按以下顺序流转：

```
                       ⬇️一一一一一一一循环一一一一一一一|
input_parse → context_assembly → agent → (tool_execution) → should_end → final → END
                                   ⬇️--------------------------------------|
```

**关键参数**：

- `MAX_TOOL_CALL_TIMES = 30`：工具调用次数上限；
- `MAX_RETRY_TIMES = 5`：重试次数上限；
- `TOOL_EXEC_TIMEOUT = 30s`：单次工具执行超时。

### 3.2 InputParseNode（输入解析节点）

#### 3.2.1 功能描述

- 接收用户输入；
- 若包含文件，调用 FilesLoader 解析；
- 调用 LLM 优化输入（improve_input）；
- 重置工具调用次数与重试次数。

#### 3.2.2 输入输出

| 项   | 内容                                                                                      |
| --- | --------------------------------------------------------------------------------------- |
| 输入  | `state.imp_ipt`、`state.files`                                                           |
| 输出  | `state.imp_ipt`（优化后）、`state.files`（解析后）、`state.tool_call_times=0`、`state.retry_times=0` |

#### 3.2.5 Pad 图

> **Pad 图符号约定**：Pad 图（Problem Analysis Diagram）采用 P—A—D—S 四级树形结构。**P**（Problem，问题）—**A**（Abstract，抽象）—**D**（Detail，细化，可多个并列）—**S**（Solution/Specification，规格/验证，可多个并列）。父节点通过垂直短线与子节点群相连，水平短线连接各并列子节点。

```
                            +----------------------------+
                            |  P : 如何把用户输入预处理为  |
                            |       工作流可消费的 state?  |
                            +-------------+--------------+
                                          |
                                          v
                            +-------------+--------------+
                            |  A : 抽象为三个子任务       |
                            |       (解析 / 计数 / 优化)  |
                            +-------------+--------------+
                                          |
        +-----------------+-------+-------+-------+------------------+
        |                 |               |               |                  |
        v                 v               v               v                  v
+----------+--------+  +-----+-------+  +----+-------+  +-----+--------+  +-----+--------+
|  D1 : 文件解析     |  | D2 : 计数    |  | D3 : 输入   |  |  S1 : 单测   |  |  S2 : 集成测试 |
|       (可选)        |  |   重置       |  |  优化(可选) |  |               |  |               |
+----------+---------+  +------+-------+  +-----+-------+  +------+-------+  +------+-------+
           |                   |                |                  |                  |
           v                   v                v                  v                  v
+----------+---------+  +------+-------+  +-----+--------+  +------+-------+  +------+-------+
| for f in files:    |  | tool_call_   |  | try:          |  | 空文件列表    |  | state 字段    |
|   suffix <- ...    |  |   times <- 0 |  |   improved <- |  |   跳过解析    |  |   应正确      |
|   parser <- ...    |  | retry_times  |  |   llm.optim() |  |               |  |               |
|   parse()          |  |   <- 0       |  | except:       |  | 截断处理      |  | LLM 失败      |
|   truncate()       |  +--------------+  |   imp_ipt <-  |  |   应正确      |  |   用原输入    |
|   append()         |                   |   原输入      |  |               |  |               |
+--------------------+                  +---------------+  +---------------+  +---------------+
                      |                       |                |                  |
                      +---------+-------------+                +------------------+
                                |                                                  |
                                v                                                  v
                  +-------------+-------------+                          +-----------+-----------+
                  | 完成 -> 解析节点          |                          | 完成 -> 集成回归       |
                  +---------------------------+                          +-----------------------+
```

#### 3.2.6 伪代码

```python
async def input_parse_node(state: State) -> State:
    """输入解析节点"""
    # Step 1: 重置计数器
    state["tool_call_times"] = 0
    state["retry_times"] = 0

    # Step 2: 文件解析
    if state.get("files"):
        parsed = []
        for f in state["files"]:
            suffix = f["suffix"].lower()
            parser = get_parser(suffix)
            result = await parser.parse(f["path"], suffix)
            result["text"] = truncate(result["text"], MAX_TRUNCATE)
            parsed.append(result)
        state["files"] = parsed

    # Step 3: 输入优化
    user_input = state["imp_ipt"]["content"]
    try:
        improved = await llm_improve.ainvoke(user_input)
        state["imp_ipt"] = HumanMessage(content=improved)
    except Exception as e:
        logger.warning(f"improve_input failed: {e}, use original")
        # state["imp_ipt"] 保持不变

    return state
```

#### 3.3.4 伪代码

```python
async def context_assembly_node(state: State) -> State:
    """上下文组装节点"""
    sid = state["session_id"]

    # Step 1: 中断检查
    if redis_client.hexists(f"interrupt:{sid}"):
        cp_id = redis_client.hget(f"interrupt:{sid}", "checkpoint_id")
        raise GraphInterrupt(checkpoint_id=cp_id)

    # Step 2: 根据轮次组装消息
    if state.get("is_first_round", True):
        memory_summary = memory_manager.get_memory(sid)
        msgs = [
            SystemMessage(content=memory_summary or ""),
            HumanMessage(content=state["imp_ipt"]["content"]),
        ]
    else:
        msgs = state["messages"] + [
            ToolMessage(
                content=state["last_tool_result"],
                tool_call_id=state["last_tool_call_id"],
            )
        ]

    state["messages"] = msgs
    state["is_first_round"] = False
    return state
```

## 第4章 Docker 沙盒调度算法

### 4.1 算法描述

沙盒池采用**预启动池化**策略：启动时预创建 N 个常驻容器（`sleep infinity`），使用时从池中弹出，执行完毕后再归还。算法需要保证：

1. 并发安全（多线程访问）；
2. 容器健康检查（自动重建）；
3. 资源清理（每次执行后清空工作目录）；
4. 超时保护。

### 4.2 类设计

```python
def execute(self, code: str, language: str = "python") -> SandboxResult:
    """在沙盒池中执行代码"""

    # Step 1: 获取容器
    with self._lock:
        if not self._pool:
            container = self._spawn_container()
        else:
            container = self._pool.popleft()
            if not self._inspect(container):
                logger.warning(f"Container {container.id} unhealthy, respawn")
                self._destroy(container)
                container = self._spawn_container()

    # Step 2: 注入代码（在锁外执行，避免长时间持锁）
    try:
        self._docker.cp(code.encode(), f"{container.id}:/sandbox/code.py")
        result = self._docker.exec(
            container.id,
            "python /sandbox/code.py",
            timeout=30,
        )
        images = self._collect_images(container.id, "/sandbox/*.png")
    except TimeoutError:
        self._docker.kill(container.id)
        raise SandboxTimeoutError("Execution exceeded 30s")
    except Exception as e:
        raise SandboxExecutionError(str(e))

    # Step 3: 清理与归还
    finally:
        with self._lock:
            try:
                self._docker.exec(container.id, "rm -rf /sandbox/*", timeout=5)
            except Exception as e:
                logger.error(f"Cleanup failed: {e}")
            self._pool.append(container)

    return SandboxResult(
        stdout=result.stdout,
        stderr=result.stderr,
        exit_code=result.exit_code,
        images=images,
    )
```

## 第6章 危险命令检测算法

### 6.1 算法描述

危险命令检测采用**黑名单 + 白名单 + 启发式规则**三层防护：

1. **黑名单匹配**：检查命令是否命中危险模式（rm -rf /、fork 炸弹等）；
2. **白名单检查**：检查命令是否在白名单（ls、cat、curl 等）；
3. **启发式规则**：检查重定向到设备文件、脚本执行拦截、sudo 联合检测等。

```python
DANGEROUS_PATTERNS = [
    r"rm\s+-rf\s+/\s*$",           # rm -rf /
    r":\(\)\s*\{",                  # fork 炸弹
    r">\s*/dev/(sda|hda|nvme)",   # 写入设备文件
    r"dd\s+if=.*of=/dev/",        # dd 写入设备
    r"mkfs\.",                      # 格式化
    r"regedit\s+/s",                # 注册表写入
    r"bash\s+-i\s+>&\s*/dev/tcp/",  # 反弹 shell
    r"sudo\s+(rm|dd|mkfs)",        # sudo 危险动词
]

ALLOWED_COMMANDS = {"ls", "cat", "head", "tail", "grep", "find",
                    "pwd", "echo", "curl", "wget", "git", "pip",
                    "python", "python3", "node", ...}

SCRIPT_INTERPRETERS = ["python", "python3", "node", "ruby", "php", "perl"]

DANGEROUS_VERBS_WITH_SUDO = ["rm", "dd", "mkfs", "fdisk", "format"]


def is_dangerous_command(cmd: str) -> bool:
    """危险命令检测"""
    cmd = cmd.strip()

    # 1. 黑名单匹配
    for pattern in DANGEROUS_PATTERNS:
        if re.search(pattern, cmd):
            return True

    # 2. 重定向到设备文件
    if re.search(r">\s*/dev/(sda|hda|nvme|xvda)", cmd):
        return True

    # 3. sudo + 危险动词
    if cmd.startswith("sudo "):
        verb = cmd.split()[1]
        if verb in DANGEROUS_VERBS_WITH_SUDO:
            return True

    # 4. 脚本执行拦截（需额外二次确认）
    first_word = cmd.split()[0] if cmd else ""
    if first_word in SCRIPT_INTERPRETERS:
        return True  # 默认拦截，由调用方决定

    return False


def is_allowed_command(cmd: str) -> bool:
    """白名单检查"""
    first_word = cmd.split()[0] if cmd else ""
    return first_word in ALLOWED_COMMANDS


def safe_execute(cmd: str) -> CommandResult:
    """安全执行入口"""
    if is_allowed_command(cmd):
        return execute(cmd)

    if is_dangerous_command(cmd):
        raise DangerousCommandError(f"Command blocked: {cmd}")

    # 既不在白名单也不在黑名单，进入宽松模式
    return execute(cmd)
```

```python
PARSER_ROUTES = {
    # 图片
    ".png": VLParser,
    ".jpg": VLParser,
    ".jpeg": VLParser,
    # 文档
    ".pdf": DoclingParser,
    ".docx": DoclingParser,
    ".pptx": DoclingParser,

    # 结构化
    ".csv": UnstructuredParser,
    ".md": UnstructuredParser,
    ".json": UnstructuredParser,
    ".xml": UnstructuredParser,
    # 文本
    ".txt": TextLoader,
    ".log": TextLoader,
}

MAX_TRUNCATE = 3000

async def parse(self, file_path: str, suffix: str) -> OutputFormat:
    """解析文件"""
    suffix = suffix.lower()

    # 1. 路由选择
    parser_cls = PARSER_ROUTES.get(suffix)
    if not parser_cls:
        raise UnsupportedFormatError(f"Unsupported suffix: {suffix}")

    parser = parser_cls()

    # 2. 解析
    try:
        result = await parser.parse(file_path)
    except Exception as e:
        raise ParseError(f"Failed to parse {file_path}: {e}")

    # 3. 截断
    if hasattr(result, "text") and len(result.text) > MAX_TRUNCATE:
        result.text = truncate(result.text, MAX_TRUNCATE)

    # 4. 包装
    return OutputFormat(
        type=result.type,           # "TEXT" / "IMAGE"
        name=os.path.basename(file_path),
        suffix=suffix,
        file_path=file_path,
        text_content=getattr(result, "text", None),
        image_content=getattr(result, "image", None),
        is_oss=is_oss_path(file_path),
    )
```

```python
    memory_path = os.path.join(self._memory_dir, f"{thread_id}.md")
    if os.path.exists(memory_path):
        os.remove(memory_path)
        return True
    return False
```

## 第10章 输入优化算法

### 10.1 算法描述

输入优化（improve_input）调用 LLM 将用户的口语化输入改写为更适合推理的清晰指令。该过程需要保留用户原意、补充隐含信息、规范表达。

### 10.2 程序流程图

```
              ┌─────────────┐
              │   (开始)    │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │ 接收用户输入 │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │ 构建提示词   │
              │ (含优化规范) │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │ 调用 LLM    │
              │ llm_imp_ipt │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │ LLM 调用    │
              │ 异常?       │
              └──────┬──────┘
                     │
              ┌──────┴──────┐
              │ No          │ Yes
              ▼             ▼
       ┌──────────┐  ┌──────────┐
       │ 返回      │  │ 返回原    │
       │ improved  │  │ 输入      │
       └─────┬────┘  └─────┬────┘
             │             │

                    │
                    ▼
              ┌─────────────┐
              │   (结束)    │
              └─────────────┘
```

### 10.3 伪代码

```python
IMPROVE_INPUT_PROMPT = """
你是一个输入优化助手。请将用户的口语化输入改写为更适合 AI 推理的清晰指令。

要求：
1. 保留用户原意
2. 补充隐含信息
3. 规范表达
4. 输出为简洁的中文（或英文，视用户输入而定）

用户输入：
{user_input}

改写后：
"""

async def improve_input(user_input: str) -> str:
    """优化用户输入"""
    prompt = IMPROVE_INPUT_PROMPT.format(user_input=user_input)

    try:
        improved = await llm_imp_ipt.ainvoke(prompt)
        return improved.strip()
    except Exception as e:
        logger.warning(f"improve_input failed: {e}, using original input")
        return user_input
```
